About Microsoft Entra ID built-in roles

Entra ID directory roles govern users, groups, applications, devices, authentication methods and Microsoft services that use Entra identities. They are distinct from Azure RBAC roles, which govern Azure resource access. This catalogue is a reference snapshot, not a view of your tenant's assignments or effective access.

Template ID, not an activated directory role ID

The built-in template ID copied here identifies the same role template across directories. Do not confuse it with the tenant-specific directoryRole.id of an activated directory-role object. A role definition is another resource type: use the identifier expected by the API, rather than substituting a template ID for every parameter named id.

See Microsoft's descriptions of directoryRole and roleTemplateId and unifiedRoleDefinition and templateId. This page does not retrieve tenant-specific object IDs.

Roles are not Graph API permissions

The microsoft.directory/... strings are directory RBAC resource actions, not Microsoft Graph OAuth scopes or application permissions such as Directory.Read.All. Check each endpoint's documented permissions and role requirements. An authorization error can have several causes; this catalogue does not diagnose token or assignment issues. Browse the separate Microsoft Graph permissions catalogue for those permissions.

Privileged classification

The Privileged badge and filter reproduce Microsoft's classification in the source snapshot. A role not flagged as privileged is not necessarily harmless. The filter count is the dataset total; the result count reflects your combined search and service filters.

Progressive action details

Actions are grouped by the service namespace before the first slash. Open a service to read a batch of actions and their recorded descriptions; show more actions or services when needed. A search inside a role covers all its recorded actions, including groups and batches not yet displayed, without changing the catalogue filters. Counts are recorded entries, not an expansion of inherited or effective permissions.

An empty action list means no actions were recorded in this snapshot, not that the role has no permissions. Refer to Microsoft Learn for its current definition.

Practical guidance

  • Prefer a narrow role over Global Administrator; most day-to-day tasks are covered by a specific administrator role listed here.
  • Scope role assignments to an administrative unit when the role supports it, so a helpdesk role does not reach the whole directory.
  • Keep at least two, and no more than a handful, of permanent Global Administrators, and exclude a break-glass account from Conditional Access.
  • Read the permissions rather than the name: several reader-sounding roles can read sensitive data, and some administrator roles are narrower than they sound.

Where this data comes from

The refresh workflow collects Microsoft's Entra ID roles reference and its action descriptions. Last refreshed is the dataset timestamp, not the last modification date of each role. Original template IDs and resource-action strings are preserved.
